# 指标定义与结果报告

本文是 BindPack 当前评测口径与操作说明。图表安排见[实验图表](实验图表.md)，方法与比较条件见[Baseline 说明](Baseline说明.md)。指标仅在实验结果保存后读取最终排名、答案和独立标签，不参与 Route、Plan、Pack 或 reader 的决策。

## 1. 报告哪些指标

| 指标 | 回答的问题 | 当前支持 |
|---|---|---|
| QA EM、token F1 | 最终答案是否正确 | 有有效答案标签且实际运行 QA 的问题 |
| 文档 Recall@K | 标注支持文档覆盖了多少 | 有有效支持文档标签且排名信息足够的问题 |
| FCR@K | 标注支持文档是否全部进入前 K 位 | 与文档 Recall 相同的有效题集 |
| DCC@K | 证据节点自身及全部依赖是否共同被覆盖 | 有独立可信 gold DAG 且排名信息足够的问题；当前仅支持 MuSiQue |
| NodeCov@K、ClosureGap@K | 节点覆盖量及其中尚未闭合的部分 | 与 DCC 相同的有效题集，作为诊断量 |

默认 K 为 **5、10、20、200**。主表优先列 5、10，其余可放补充结果。Recall/FCR/DCC 是并列的观察维度，不构成串行算法；FCR 不向 DCC 提供输入。FCR 已见于 [CatRAG 正式论文](https://aclanthology.org/2026.findings-acl.290/) 的评测定义，不作为本文新提出的指标。DCC 作为结构诊断口径，避免未经文献核查声称首创。统一使用名称 DCC，不另以 ECC、DECC、DCR 重复命名。

全部聚合均先逐题计算，再按问题宏平均；每个指标使用自己的有效分母。`null` 表示不可评，`0` 表示有效评测中的失败。空标签、缺失图、非法标注或未知排名尾部不能直接填 0，也不能按空集合“真空为真”填 1。表格需注明有效题数与标注覆盖率。

## 2. 文档身份、排名与预算

对问题 q，最终有序排名为 \(L_q=[d_1,\ldots,d_m]\)。先取原始排名位置的前 \(\min(K,m)\) 项，再取集合，得到 \(R_K(q)\)。**先切片、后取集合**；重复文档占排名位置，但不重复计分，不在评测时去重后回填新文档。报告同时记录重复位置与重复题数。

当前文档身份采用完整规范字符串的精确匹配：`title + "\n" + text`，不是仅标题、答案字符串命中或语义相似匹配。

- HotpotQA 的正文为 `"".join(sentences)`，句间不加空格。
- 2WikiMultiHopQA 的正文为 `" ".join(sentences)`，句间加一个空格。
- MuSiQue 使用 `paragraphs[*].title` 与 `text`，缺少有效 `text` 时使用 `paragraph_text`。

空白差异可能导致失配。所有方法应使用同一 canonical passage ID 到完整文本的冻结映射，保留映射版本，不能让某个方法单独按标题评测。当前映射版本为 `canonical-passage-exact-v1`。

| 字段或参数 | 含义 |
|---|---|
| `retrieval_top_k`，默认 200 | 最终检索排名长度上限 |
| `result_top_k`，默认 10 | `result.json` 中 `docs`、`doc_scores` 的展示长度 |
| `candidate_output_top_k`，默认 200 | `candidate_docs` 保存最终 `solution.docs` 的较长前缀，并非 Route 原始候选并集 |
| `qa_top_k`，默认 5 | reader 实际读取最终排名的前缀长度 |
| `gold_document_ranks` | 每篇 gold 文档在完整最终排名中的最早位置；`null` 表示未出现 |

离线评估优先读取 `candidate_docs`，不存在时读取 `docs`，并校验 `gold_document_ranks` 的文档集合、正整数位置、唯一性以及与已保存前缀的一致性。可信的完整排名 gold ranks 可以补足被截断的展示结果。

如果只保存了 10 条且没有足够的 gold rank 信息，未出现在其中的文档在 K=20/200 处是**未知**，不能认定检索失败：相应指标记 `null`，原因为 `insufficient_exported_ranking_coverage`。如果完整返回排名已保存且实际不足 K，则按全部实际返回项计算，并报告长度不足；不得把“尾部没保存”当成“系统没返回”。当前批量结果通常不保存实际完整排名长度，`actual_ranking_length_unknown_count` 因而可能非零，即使 gold ranks 已足以算指标。

K 表示原始 passage 的排名位置数，不是 tokens、三元组数、计划节点数或证据包数。摘要/图节点型方法只有能追溯到实际使用的原始 passages 才能使用这套文档指标；展开源文档后的预算也必须计入。无法可靠映射时保留 QA 指标，文档指标标 N/A。

## 3. 文档 Recall 与 FCR

令 \(S_q\) 为问题 q 去重后的非空 gold supporting-document 集合：

\[
\operatorname{Recall}(q,K)=\frac{|R_K(q)\cap S_q|}{|S_q|},\qquad
\operatorname{FCR}(q,K)=\mathbf{1}[S_q\subseteq R_K(q)].
\]

令 \(Q_{\mathrm{doc},K}\) 为该 K 下标签有效且文档是否命中均可观测的问题集合，则：

\[
\operatorname{Recall@K}=\frac{1}{|Q_{\mathrm{doc},K}|}\sum_{q\in Q_{\mathrm{doc},K}}\operatorname{Recall}(q,K),\qquad
\operatorname{FCR@K}=\frac{1}{|Q_{\mathrm{doc},K}|}\sum_{q\in Q_{\mathrm{doc},K}}\operatorname{FCR}(q,K).
\]

分母为有效问题数，不是所有命中文档数；没有有效题时汇总为 `null`。FCR 每题等价于 Recall=1，但**宏平均 FCR 不能由宏平均 Recall 还原**。`all_gold_in_top5`、`all_gold_in_top10` 是导出中的非空 gold 完整性标志，离线 evaluator 仍根据冻结标签与排名统一重算。

FCR 衡量标注支持集合的共同出现，不检查依赖顺序、实体绑定、语义蕴含或 reader 实际利用情况。需要四篇互不相同文档的题在 K=2 时 FCR 必为 0，应解释这种预算可达性。主协议只使用数据集给定集合；`AnySet-FCR` 仅能在独立标注确实给出多组充分证据时另报，当前报告未实现，不能把多组替代证据的并集都当必需。

注意原在线 `retrieval_eval.py` 对空 gold 记 0，汇总还会舍入到四位小数；新报告对无效/空标签采用不可评口径并保留未舍入均值。原导出数值存于 `original_exported_metrics` 供核对；不要把两种口径混用，统计分析使用逐题原值。

## 4. DCC、NodeCov 与 ClosureGap

### 4.1 独立 gold DAG 与证据映射

对问题 q，使用与被评方法无关的 gold DAG \(G_q^*=(V_q,E_q)\)，边 \(u\to v\) 表示完成 v 必需先具备 u 的信息。所有前置节点默认是 **AND 依赖**。纯计算/比较终结节点不应占证据节点分母；若从更大图投影为证据图，必须保留经过计算节点的传递依赖，不能简单删边。

每个证据节点 v 有独立标注的充分证据束族 \(\mathcal B_v\)。一个 bundle 中的文档必须全部出现，不同 bundles 之间可任选一个：

\[
c_v(q,K)=\mathbf{1}[\exists B\in\mathcal B_v:B\subseteq R_K(q)].
\]

这表示“bundle 内 AND、bundle 间 OR”；每个 bundle 为单文档时退化为合法支持文档 alternatives 的非空交集。当前 MuSiQue 构建器给每个节点生成一个单文档 bundle，不会推测额外替代文档或缺失计算节点。节点缺支持/计算标注时直接判图不可评。

### 4.2 闭合覆盖与聚合

令 \(\operatorname{Anc}(v)\) 为 v 的全部祖先，定义：

\[
\widetilde c_v(q,K)=c_v(q,K)\prod_{u\in\operatorname{Anc}(v)}c_u(q,K),\qquad
\operatorname{DCC}(q,K)=\frac{1}{|V_q|}\sum_{v\in V_q}\widetilde c_v(q,K).
\]

根节点的空祖先乘积为 1。聚合为有效图与可观测排名题集 \(Q_{\mathrm{dag},K}\) 上的逐题宏平均：

\[
\operatorname{DCC@K}=\frac{1}{|Q_{\mathrm{dag},K}|}\sum_{q\in Q_{\mathrm{dag},K}}\operatorname{DCC}(q,K).
\]

图为空、非 DAG、节点身份重复、前置节点缺失、证据映射无效或排名信息不足时为不可评，记录具体原因。不能用检索结果修补 gold 图。报告在相同有效图子集另给 Recall/FCR，避免不同分母产生误导。

诊断量定义为：

\[
\operatorname{NodeCov}(q,K)=\frac{1}{|V_q|}\sum_v c_v(q,K),\qquad
\operatorname{ClosureGap}(q,K)=\operatorname{NodeCov}(q,K)-\operatorname{DCC}(q,K).
\]

始终有 \(0\le\operatorname{DCC}\le\operatorname{NodeCov}\le1\)，ClosureGap 非负。一般不能用文档 Recall−DCC 代替 ClosureGap：只有节点与文档一一对应且 gold 集合一致时 NodeCov 才等于 Recall；这一特例才有 FCR≤DCC≤Recall。

### 4.3 定义示例与边界

以下是数学例子，不是实验结果。链 \(s_1\to s_2\to s_3\)，每个节点对应不同文档：

| 命中节点 | 文档 Recall | FCR | NodeCov | DCC |
|---|---:|---:|---:|---:|
| s₁、s₂、s₃ | 1 | 1 | 1 | 1 |
| s₁、s₂ | 2/3 | 0 | 2/3 | 2/3 |
| s₁、s₃ | 2/3 | 0 | 2/3 | 1/3 |
| s₂、s₃ | 2/3 | 0 | 2/3 | 0 |

对菱形 \(s_1\to\{s_2,s_3\}\to s_4\)，命中 s₁、s₂、s₄ 而缺 s₃ 时 DCC=2/4。不能以一条任选路径的覆盖代替全部祖先闭合。

固定图与排名时，逐题 DCC、NodeCov、Recall/FCR 随 K 增大不下降；比较宏平均曲线时还要保证有效题集一致。无依赖边时 DCC=NodeCov，可作为负对照。若两者高度重合，应如实降低 DCC 的附加信息定位，不能改定义制造差异。预标注多合法图的 `AnyGraph-DCC` 当前未实现。

DCC 不要求 baseline 有 planner，也不检查检索时间顺序或推理忠实性。Pack 在预测 plan/proofs 上的内部闭合目标与独立 gold-DCC 不同；内部闭合增加不保证 gold-DCC 或答案质量提高，来源检查也不等于语义蕴含保证。

## 5. 各数据集的 gold 标签

| 数据集 | 文档标签 | DCC 当前口径 |
|---|---|---|
| MuSiQue | `paragraphs[*].is_supporting` 与完整段落文本 | 用原生 `question_decomposition` 构建独立 gold DAG |
| HotpotQA | `supporting_facts` 标题映射到 `context` 完整正文 | 缺少经独立验证的依赖图，DCC/NodeCov/ClosureGap 为 `null` |
| 2WikiMultiHopQA | 同上 | `evidences`/`evidences_id` 的排列不能直接视为串行依赖；验证前结构指标为 `null` |

MuSiQue 的 `#i` 引用表示 decomposition 的 **1-based 位置**，不是 step 的全局 `id`；`paragraph_support_idx` 映射 `paragraphs[*].idx`，不是数组位置。构建器检查引用必须指向更早步骤、支持 idx 唯一且存在、段落明确 `is_supporting=True`、全部标注支持段落均有映射，以及规范文本在冻结 corpus 中精确存在。图版本为 `musique-native-position-dag-v1`。格式校验不等于人工语义验证，仍建议抽检。

HotpotQA/2Wiki 的不可评原因为 `dataset_has_no_verified_gold_dependency_graph`。**重新跑检索也不能补出缺失的 gold DAG**；只能使用独立标注验证后的图。不得用 BindPack 预测 plan、source binding、winning branch 或 package eligibility 当 gold，也不得根据最终答案补图或回流重排。

通用标签适配器还支持 NQ/PopQA：NQ 风格 `contexts` 没有任何显式支持标记为真时回退到全部 contexts；paragraph 格式只排除显式 `is_supporting=False` 的项。报告保存 `gold_documents.policy`，不能把这些宽松回退一概称为人工最小充分证据。单跳任务具有多个替代支持文档时，FCR 可过严，应带注释使用。

## 6. QA EM/F1 与上下文条件

EM 采用英文答案规范化：小写、删除 ASCII 标点、删除英文冠词 a/an/the、合并空白；与任一 gold answer/alias 完全相等即成功。token F1 使用相同规范化后的词袋交集，计入重复 token；EM/F1 均先在 aliases 上取最大值，再逐题宏平均。不是 substring correctness 或 LLM 语义裁判。

离线报告从冻结 benchmark 重建答案标签，校验已导出的 `gold_answers`。未运行 `rag_qa` 时记 `answer_generation_not_run`，缺少有效 aliases 时记 `missing_answer_labels`，QA 为 `null`。在正常非空 gold 上，空预测是失败并记录 `empty_prediction_count`，不能删题。实现边界：两边规范化后均为空时 EM 可为 1，token F1 为 0；正式数据需检查这类标签。

当前没有实现 JSR。可选严格联合指标应明确写作：

\[
\operatorname{JSR_{EM}@K}=\frac1{|Q_{\mathrm{joint},K}|}\sum_q\operatorname{FCR}(q,K)\operatorname{EM}(q;R_K).
\]

答案必须由相同 Top-K 上下文生成。不能把一次 reader@5 的答案用于 JSR@5/10/20/200；若仅计算 FCR@10 与 EM(reader@5) 的交集，应使用这个完整名称。预算曲线的 QA F1 也需要各预算重新生成答案，单纯离线切片只能重算证据指标。

## 7. 必须披露的实验条件

- **Oracle hop：** 当前 MuSiQue 入口读取 gold decomposition 长度作为每题 2/3/4 节点的预算输入，导出 `hop_provenance.kind=per_question_oracle`，会影响检索与分解。不能写成完全无测试标签的推理。HotpotQA/2Wiki 固定 2 是数据集先验，不是逐题串行跳数；decomposition 节点数也不等于 DAG 深度。
- **无 oracle 控制：** 若要报告只用问题的标准条件，应另实现并运行不读取测试分解标签的固定/预测预算策略；改表头不能消除已有侧信息。各方法获得哪些先验须一致或明确披露。
- **冻结 corpus：** 入口可补入 corpus 中缺失的 gold 文档；需要记录 `gold_completion_added`、最终 corpus 摘要，并把相同 corpus 提供给所有 baseline。`sample_only` 小语料仅适合 smoke，不能与完整 benchmark corpus 的论文值直接比较。给定 benchmark corpus 也不等于全维基。
- **可比性：** 固定问题清单、模型、reader、证据/token 预算、prompt、缓存条件与错误处理。其他论文原值只有在条件写清时作为参考；不可与本地统一结果混成未经控制的胜负排名。

源信息应保留 dataset/corpus SHA、split、sample IDs/order、seed、代码版本、模型与方法参数。缺标注和执行失败分别统计；不得按结果删题。报告先保存原始 [0,1] 逐题值，表格统一转为百分数，差值用“百分点”。关键差异建议补同题配对 bootstrap 95% CI；bootstrap、多 seed 汇总、相关性和类型/深度分层不属于当前报告自动实现的指标。

现有 `retrieval_seconds` 是累计检索计时，不是完整 QA 延迟，也没有逐题 P95；`llm_request_stats` 是请求/缓存/重试统计，不是完整输入输出 token 计费。不能直接拿来填完整效率表；需按阶段计量，离线建库成本与在线查询成本分列，详见[实验图表](实验图表.md)。

## 8. 每组报告的文件与字段

每个结果目录保存 `result.json`；指标后处理另写以下文件，不改检索结果或排名：

| 文件 | 内容 |
|---|---|
| `report.json` | EM/F1、Recall/FCR/DCC/NodeCov/ClosureGap 汇总、有效分母、来源与版本 |
| `metrics_details.json` | 逐题标签、gold 图、命中/未知文档、闭合节点与缺失祖先、QA、排名诊断 |
| `.metrics_report.lock` | 防止多个保存钩子/watcher 并发改写同组报告的目录锁，正常存在即可 |
| `report_error.json` | 后处理失败时的独立记录；修复来源问题后可重试，原实验结果保留 |

`report.json` 的主要读取路径：

| JSON 路径 | 含义 |
|---|---|
| `metrics["FCR@5"]`、`metrics["DCC@10"]` 等 | 未舍入比例 [0,1]，不可评为 `null` |
| `metrics.ExactMatch`、`metrics.F1` | 答案宏平均 [0,1] |
| `metrics_percent` | 对应百分数；`0.879` 对应 `87.9`，不重复乘 100 |
| `coverage.sample_count`、`coverage.qa_n` | 总题数与 QA 有效题数 |
| `coverage.document_labels_valid`、`coverage.graph_labels_valid` | 标签本身有效数量；不等同每个 K 均可评 |
| `coverage.per_k["5"].document_n`、`.graph_n` | 该 K 的文档/图有效分母与 coverage fraction |
| `coverage.per_k["5"].document_unavailable_reasons`、`.graph_unavailable_reasons` | 各类不可评原因及题数 |
| `coverage.per_k["5"]` 中 `exported_prefix_below_k_*`、`actual_ranking_*` | 已存前缀不足、真实长度不足或未知的诊断 |
| `dag_subset_document_metrics["5"]` | 与结构指标相同有效子集的 `n`、Recall、FCR，均为原始比例 |
| `inputs`、`sample_alignment` | result/标签/corpus/协议/验证文件 SHA、状态、样本对齐与冻结身份说明 |
| `evaluator`、`protocol`、`details.sha256` | evaluator 版本与摘要、匹配/聚合/reader 口径及逐题文件摘要 |
| `original_exported_metrics` | 原结果中的在线 QA/Recall 汇总，便于口径核对 |

在 `metrics_details.json` 中逐题读取 `per_query[i].at_k["5"]`：包含 Recall/FCR/DCC/NodeCov/ClosureGap、`document_valid`/`graph_valid`、不可评原因、`hit_gold_docs`/`missing_gold_docs`/`unknown_gold_docs`、`covered_nodes`/`closed_nodes`/`missing_ancestors` 与逐节点诊断。`per_query[i].gold_graph` 保存独立图来源、label SHA、nodes/edges；`.ranking` 保存前缀来源、重复率和长度可知性；`.qa` 保存 QA 有效性与逐题分数。

## 9. 离线补算与自动报告

在仓库根目录执行，CPU 即可，不导入 GPU 检索栈：

```bash
# 指定一组已完成结果；默认 K=5/10/20/200
python scripts/report_metrics.py \
  --case outputs/3multi_hop_datasets_results_10_5/cases/hotpotqa/full

# 当前四组 BindPack 及 HippoRAG 复现；未 validated 的目录跳过
python scripts/report_metrics.py \
  --cases-root outputs/3multi_hop_datasets_results_10_5/cases

# 在每组完成后补报告，批次完成后最终扫描一次并退出
python -u scripts/report_metrics.py \
  --cases-root outputs/3multi_hop_datasets_results_10_5/cases \
  --watch --interval 30 \
  --batch-dir outputs/3multi_hop_datasets_results_10_5/metadata/stage_ablations_qwen3_reuse
```

可用 `--ks 3 5 8 10` 重算证据预算、`--case-names` 明确选择其他历史目录；默认当前目录名为 `full`、`wo_route`、`wo_plan`、`wo_pack`、`hippporag2_reproduce`。不要把同一 baseline 的其他历史目录视为本轮结果。单组可通过 `--manifest`、`--data-path` 指定来源，但仍必须通过冻结 SHA 和身份校验；watch 也支持 `--runner-pid`，父进程退出后最终扫描并退出。

CLI 要求 `validated.ok`，核对 result SHA、case 协议、冻结 sample manifest、样本 ID/索引/问题顺序、benchmark 与 corpus 摘要。身份不符会拒绝写报告；写入使用原子替换与文件锁，可重复执行，来源和 evaluator 未变化时复用有效报告。它不启动、停止或重跑模型，不改 `result.json`、`validated.ok` 或检索协议。单独评测入口在保存后的 hook 可生成 `validated_result=false` 的初始报告；无冻结 manifest 时明确记录 standalone 来源，不能冒充冻结批次校验。

新入口保存结果后、主 runner 校验每组后均会尝试报告。正在运行且已加载旧代码的进程可以用 CPU watcher 补算，不必重启；有足够最终排名/gold ranks 的旧结果也不必重跑。缺失尾部只影响相应 K 的可评性，缺 gold DAG 则需要独立标签，二者应分别处理。

旧批次断点继续时，源码指纹必须匹配。`configs/metrics_reporting_update.json` 只为已核对的特定旧批次允许**精确列举且指纹一致的纯报告更新**，恢复过程另写 `reporting_protocol.json`，保留原检索协议。非报告文件、模型、参数或输入变化仍拒绝恢复；此机制不能用于跨算法变更沿用旧结果。文档整理不在检索源码指纹范围内。
