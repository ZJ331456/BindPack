## 2. 框架图必须与代码一致

当前离线阶段从 corpus 建立 OpenIE、向量与图索引；在线阶段为：

1. Route 从 query/facts、seeds、bridge 与有限迭代得到初始排名，并构造静态 QD/PCQD 检索线索。
2. Plan 在最终 Route fusion/path-set **之前**读取初始 base 候选及子问题的独立 DPR 候选；验证依赖 DAG，按拓扑层执行、绑定中间答案并核验来源。绑定后的依赖 DPR 可以引入新候选。
3. Route 完成 track fusion/path-set；Pack 读取最终主排名及同一份 Plan state，进行 coverage/redundancy greedy、有限 DAG package 优化与最终 safeguard。
4. 最终排名送入可选 reader，随后计算检索和问答指标；独立 gold-DAG evaluator 仅用于离线评测。

因此不要画成“最终 path-set → planner → 只保留 verified passages → Top-K”的单线。候选中只有一部分有合格 proof；source verification 和预测依赖闭合不保证语义蕴含。没有 facts 时可以 dense fallback，但 Plan/Pack 仍可能运行；失败、缺 proof、预算耗尽也不代表某模块对每题都成功激活。

Pack 当前先优化 Top5、保留 Top2，再优化 Top10、固定已优化 Top5。局部 DAG 重排保持候选集合和 Top200 集合，并不增加新的检索候选。当前默认 `pack.review_mode=off`，末端 Support / semantic veto 已单独关闭；只有显式启用 `standard` 或 `suffix_stop` 时，最后 safeguard 才可能提出一次 Top10 内交换并请求审核。内部预测 plan 的 closed coverage 不能作为 gold-DCC 报告。

## 3. 四组 BindPack 消融的严格定义

| 名称 | `stage_ablation` | 保留与移除的实际内容 |
| --- | --- | --- |
| Full BindPack | `full` | 完整 Route、Plan/Bind、coverage/redundancy greedy、DAG package 与最终 safeguard |
| w/o Route | `wo_route` | 使用 fact-frequency seeds、DPR restart 和固定 damping 的基础图候选适配器；移除增强 seed/IDF、bridge、iterative、QD/PCQD、path-set；保留 Plan/Pack |
| w/o Plan | `wo_plan` | 不规划、不执行依赖 DPR、不绑定中间答案、不产生 Plan proof；保留 Route 与 flat coverage/redundancy Pack；没有计划输入，跳过 DAG package |
| w/o Pack | `wo_pack` | 保留 Route/Plan 候选与状态，按原 base/goal pointwise 融合分数排序；关闭 greedy、DAG package 和最终 safeguard |

`wo_plan` 仍保留最终 safeguard，但没有 Plan proof 保护；不能称为完整 DAG Pack。`wo_pack` 关闭 safeguard，避免最后交换补回被移除的 Pack。Plan 与 DAG Pack 有真实依赖，因此这四组不是无交互的 `2³` 组合，也不能预设消融成绩必定下降。

`wo_route` 是本项目内的基础候选适配器，**不是外部 HippoRAG2 的完整独立复现**。`stage_ablation` 只有上述四个值；复用 Shell 额外执行的 HippoRAG2 是方法 baseline，默认结果目录名为 `hippporag2_reproduce`，不是第五个阶段模式。历史目录中的旧 case 不属于当前枚举，也不能仅凭目录名合并为同一方法。

## 4. 新增分析的具体协议

### 效率与成本

至少统一硬件、并发、模型、reader、上下文预算和输入样本。分别报告冷缓存与暖缓存条件；LLM API cache、索引/lookup cache 与模型加载均应说明。模型启动和离线建库与在线查询分开计时。

Table 3 建议列 QA F1、平均/P50/P95 端到端查询延迟、每题 LLM 请求次数、输入/输出 tokens、重试及命中率。离线部分单列 OpenIE/embedding/构图耗时、LLM tokens 与存储。索引复用省下的是本次评测的建库开销，不能记成该方法离线成本为零。

现有 `retrieval_seconds` 是累计检索计时，**不等于完整 QA 延迟，也没有逐题延迟分布**；`llm_request_stats` 有部分请求/缓存/失败统计，但没有完整 token 汇总，计数还需在建库和查询边界取差。现有日志不能直接填成完整成本表，需要补计量或重新测量。

2026-10-24新增独立的[Full计量入口](../scripts/MEASURED_RUNS.md)：`scripts/run_bindpack_measured.sh`。新批次保存逐题连续检索/规划/Pack+Reader延迟、物理请求与逻辑调用及缓存命中、真实usage、embedding计量、建库阶段耗时、实际证据tokens与CPU/RAM/GPU采样，并冻结源码/配置/输入和逐题断点。本次只安排HoVer Full；旧三数据集结果不会因此补出未采集的成本。共享GPU采样不等于独占GPU成本，没有单价的货币费用仍为N/A。方法、计量边界及恢复命令见该入口说明。

上述限制针对历史 BindPack 日志。2026-10-19 完成的 Standard Retrieval 新入口已独立计量16组、16000题的 reader@5：连续检索+reader平均/P50/P95延迟、逻辑调用与HTTP尝试/重试、真实输入/输出tokens、原始索引构建时间、本次复用准备时间、索引体积及证据预算均已保存到各组 report.json。[@5 HTML汇总的效率与成本图](../../baseline/scripts/outputs/standard_full_20261019/results_at5.html#efficiency) 可按四数据集切换，分位数不跨数据集平均，原始建库与本次复用成本分图展示，支持SVG/PNG下载；成本明细见 [CSV](../../baseline/scripts/outputs/standard_full_20261019/results_at5.costs.csv)。货币费用及独占GPU时间仍为N/A。该批计量不代表 BindPack 和八个结构基线已经完成同协议成本实验。

### 证据预算

先在 MuSiQue 比较 K=3/5/8/10，并记录实际输入 tokens；passage 数相同不表示 token 数相同。另做固定 token budget 对照时，应给所有方法同一截断规则。

FCR/DCC 可从保存充分的最终排名离线计算不同 K；**QA F1 必须让 reader 使用对应 Top-K 重新回答**，不能把 reader@5 的一次答案用于全部预算。当前 Pack 面向 Top5/Top10 优化：只改变 reader 的 K，结论是“现有排序在不同 reader 预算下的表现”；若要声称 Pack 随预算自适应，还需实现并同步改变 Pack 的优化预算，再在新协议中运行。

### 依赖机制与额外信息控制

Figure 3 的第一个子图按独立 gold DAG 的深度分层，标出样本量；decomposition 节点数与依赖深度不是同一概念。第二个子图在相同或明确分箱的 NodeCov 条件下比较 DCC，检查覆盖节点数量相近时是否仍存在闭合差异。若 DCC 与 NodeCov 高度重合，如实降低其额外解释价值。

新入口按各数据集的参考标注读取每题 hop：HotpotQA 为去重支持标题数，2Wiki 为支持事实条数的 2/4 分桶，MuSiQue 为 decomposition 长度，HoVer 为原生 `num_hops`。这四种来源均记录为 **oracle-hop 辅助条件**，影响检索与分解预算；它们不等于串行 DAG 深度。尤其 2Wiki 的“4-hop”是本项目约定的证据数桶，不能据此推断四步串行依赖。需要新增不读取测试支持/分解/hop 标注的固定预算或预测预算控制，并披露基线是否获得相同信息；不能通过改实验名称冒充已完成。

历史批次 `3multi_hop_datasets_results_10_5` 使用旧规则：HotpotQA/2Wiki 固定 2，MuSiQue 使用旧文件的 decomposition 长度。历史结果和正在运行的任务保持原协议；新规则下的 2Wiki 结果必须另开目录，不能拼入旧消融表。

### 案例与 Backbone

案例展示 gold 依赖图、相同预算下的真实检索文档、绑定来源与引文、最终证据包和答案。成功案例用于解释过程；失败案例可展示候选缺失、错误绑定或闭合后回答错误。不能用方法生成的 plan 替代 gold 图，也不能把两个精选案例作为总体统计证据。

Backbone 实验应检验“每种 embedding 下，BindPack 相对使用相同 embedding 的基线是否仍有增益”。只比较 BindPack 自己换模型的分数不能充分回答该问题。更换 embedding 需要匹配的向量索引，维度相同也不能混用；现有 Qwen 专用 Shell 不直接支持任意 Backbone 扫描，该实验还需单独适配与记录协议。

## 5. 当前数据、配置与公平条件

新实验默认读取仓库内 `/root/BindPack/datasets/<dataset>.json` 和 `<dataset>_corpus.json`，四种格式及 Hop 统计见 [数据集说明](../datasets/README.md)。默认实验清单仍为三个问答数据集；显式 `--datasets hover` 才运行 HoVer。数据目录可由 `--datasets-dir` 覆盖。

| 数据集标识 | 本地问题数 | Corpus 篇数 | 新入口 Hop 规则与分布 |
| --- | ---: | ---: | --- |
| `hotpotqa` | 1000 | 9811 | `supporting_facts` 去重标题数；2:1000 |
| `2wikimultihopqa` | 1000 | 6119 | `supporting_facts` 条数为2→2、≥4→4；2:765 / 4:235 |
| `musique` | 1000 | 11656 | `len(question_decomposition)`；2:518 / 3:316 / 4:166 |
| `hover` | 1000 | 9440 | `num_hops`，核对去重支持标题数；3:559 / 4:441 |

HoVer 使用 `hover_id` 对齐样本，检索文本为 `claim`，目标是 `SUPPORTED`/`NOT_SUPPORTED`；不读取 `hotpotqa_question` 作为查询，也不把 `hotpotqa_answer` 当目标答案。`NOT_SUPPORTED` 表示未获支持，不能一概解释为已被证伪。原生2-hop HoVer 样本也受支持，当前本地文件只有3/4。

| 数据集标识 | 本地问题数 | 冻结 corpus 篇数 | 源图节点 | 源图边 |
| --- | ---: | ---: | ---: | ---: |
| `hotpotqa` | 1000 | 9811 | 103954 | 1094530 |
| `2wikimultihopqa` | 1000 | 6119 | 55276 | 738087 |

这些是旧源 metadata 的记录；启动仍要核对实际文件和摘要。“全量”指每个本地 1000 题文件的全部样本，**不是上游官方 split 全部问题**。历史批次冻结的路径为 `/root/datasets`；它与新默认目录不能直接互换。当前新旧 HotpotQA、2Wiki query 文件摘要相同；MuSiQue query/corpus 的字节摘要不同，但完整 JSON 内容、样本顺序、问题、分解和有序文档相同，差异仅在序列化格式。

新批次复用索引可接受这种**经验证的完整 JSON 等价**：旧文件必须仍匹配旧 manifest 的字节 SHA，新文件必须匹配新批次的字节 SHA，二者完整 JSON 的规范摘要一致，原有模型、资产、有序文档和样本身份检查仍全部执行。批次协议的 `shared_indexes[*].serialization_equivalence` 记录 `kind=exact_json_value_equivalence` 和新旧文件路径、字节/JSON摘要；规范化仅对JSON对象键排序，不改数组顺序或正文。这样新批次可复用三个现有索引，无需仅因格式变化重建；旧协议和结果不改写。实际内容或顺序改变则拒绝，不能仅凭文件名、问题数或 hop 分布相同判为等价。小语料 smoke 不能当作正式 benchmark。

所有方法固定同一问题顺序、corpus、chunk 与 canonical passage 映射、gold labels、embedding 条件、reader、prompt、K 和 token 截断。FCR 默认输出 @5/10/20/200；DCC 使用独立 MuSiQue gold DAG，HotpotQA/2Wiki/HoVer 无可信依赖图时为 `null`。指标分母、缺标注原因和 provenance 约束详见 [指标说明](指标说明.md)。

正式完整语料应检查是否补入 gold 文档；若发生补入，记录数量与 corpus 摘要，并让所有方法使用同一冻结语料。来源只能映射到 summary/triples 而无法追溯原始 passages 的方法，不能免费按其全部底层文档计 Recall/FCR/DCC，应标明不可评并单独比较 QA。 2026-10-20修复的RAPTOR入口使用完整passage叶子与原生树遍历，已具备实际原文排名；八个结构基线的Recall/FCR均列为预检必需项，MuSiQue还要求DCC/NodeCov/ClosureGap。旧RAPTOR摘要单位结果单独归档，不与新原文QA混用；其他数据集缺可信gold DAG时仍不能编造依赖指标。

| 配置位置 | 职责 |
| --- | --- |
| `src/bindpack/configuration/defaults.json` | `runtime/candidates/route/plan/pack` 方法默认数值唯一来源 |
| `src/bindpack/configuration/*.py`、`config.py` | 类型、范围校验，组合并加载 `BindPackConfig` |

资源覆盖顺序为命令行 > 实验 JSON 的 runtime/evaluation > 方法文件 > 包内默认。算法权重与预算经方法 JSON 修改；更改后使用新输出目录。当前默认返回 200 篇、展示 10 篇、reader Top5/一次回答；三个数字是不同预算。

当前默认 LLM 为 `/root/models/Qwen3-8B`，服务 ID `qwen3-8b`，地址 `http://127.0.0.1:8035/v1`；embedding 为 `/root/models/Qwen3-Embedding-8B`，本地 SentenceTransformer 加载。执行 Python 为 `/root/anaconda3/envs/rag/bin/python`。固定设置包括 embedding batch=4、OpenIE/预取并发=8、生成上限 2048；`openie_strict=false`、`optimized` prompt、`structural` 校验不代表所有关系都已语义核验。

## 6. 运行入口与保存位置

下面是复现命令，**不要在已有任务运行时重复启动同一批次**。脚本不会自动启动模型服务。现有任务无需为了查看或补算报告而重启。

在 `/root/BindPack` 下执行：

```bash
# 新建共享索引：先查看命令；默认 retrieve，仅检索指标
bash scripts/run_bindpack_ablations_qwen3.sh --dry-run
bash scripts/run_bindpack_ablations_qwen3.sh \
  --smoke --datasets hotpotqa --sample-size 1

# 新目录正式运行四组，开启 reader QA
bash scripts/run_bindpack_ablations_qwen3.sh \
  --eval-mode rag_qa --out-root outputs/stage_ablations_qwen3_qa

# HoVer 独立新批次：仅四组 BindPack，不启用外部 HippoRAG2
bash scripts/run_bindpack_ablations_qwen3.sh \
  --datasets hover --eval-mode rag_qa \
  --out-root outputs/hover_qwen3_annotation_hops --dry-run
# 确认命令后去掉 --dry-run 才会建库/运行；当前任务无需因此重启

# 新规则另开批次：MuSiQue 的序列化差异必须通过完整 JSON 等价校验
# 复用 Shell 默认四组 BindPack + 独立 HippoRAG2，含 QA
bash scripts/run_bindpack_four_cases_reuse.sh \
  --datasets hotpotqa 2wikimultihopqa musique \
  --out-root outputs/annotation_hops_reuse --dry-run

# 完整旧索引上的小样本预检，输出与正式批次分开
bash scripts/run_bindpack_four_cases_reuse.sh \
  --datasets hotpotqa 2wikimultihopqa musique --smoke \
  --out-root outputs/annotation_hops_reuse_smoke --dry-run

# 只恢复已按新规则启动且已停止的新批次，保留相同参数与代码
bash scripts/run_bindpack_four_cases_reuse.sh \
  --datasets hotpotqa 2wikimultihopqa musique \
  --out-root outputs/annotation_hops_reuse --resume --dry-run
```

以上带 `--dry-run` 的命令只预览，确认后去掉该参数才会运行。新建入口的默认 smoke 从选中问题 context 建 tiny corpus；复用入口的 smoke 仍使用完整旧 corpus/索引，默认每数据集 2 题。smoke 输出名称必须含 `smoke`，不能与正式目录混用。

不要用当前源码对历史整批输出执行无参数 `--resume`：旧批次的 Hop 源码与新策略不同，恢复校验会拒绝。MuSiQue 的 JSON 等价复用只用于新批次的索引输入校验，不会让旧源码协议自动升级。正在运行的旧父进程已固定其冻结子进程源码快照，并有独立回执校验，继续遵循旧协议；这不意味着新源码可自动恢复旧批次。上述新输出目录不会覆盖旧组结果。

历史复用源为 `outputs/3multi_hop_datasets_results_10_5/shared_indexes/{hotpotqa,2wikimultihopqa,musique}`，实际模型子目录为 `qwen3-8b__root_models_Qwen3-Embedding-8B`。其中没有 HoVer 索引；HoVer 需先走新建入口。复用前校验模型、数据/corpus、图/向量/OpenIE 和样本身份，不调用建库入口；格式差异须按第5节证明完整 JSON 等价。旧 Qwen 索引不能替换成 NV-Embed-v2 索引，也不能放宽检查来接受实际内容变化。

### 模型服务配置参考

先确认现有服务，避免重复占用 GPU。确需新建服务时，在独立终端启动：

```bash
PYTHONPATH=/root/.cache/pathcondrag/runtime_deps_qwen3_tf4513 \
/root/anaconda3/envs/vllm/bin/python -m vllm.entrypoints.openai.api_server \
  --host 127.0.0.1 --port 8035 \
  --model /root/models/Qwen3-8B --served-model-name qwen3-8b \
  --trust-remote-code --dtype bfloat16 --max-model-len 8192 \
  --gpu-memory-utilization 0.55 --enforce-eager \
  --max-num-batched-tokens 2048 --max-num-seqs 8 --generation-config vllm
```

等 `/v1/models` 返回 `qwen3-8b` 后再加载 embedding，避免共同使用 GPU 时影响服务初始化的显存测量。这里是本机已使用的资源配置，不保证适合其他硬件；使用原生兼容 Qwen3 的 Python 环境时可在实验配置中清空 `runtime_deps`。

现行服务脚本为 `scripts/start_vllm_qwen3.sh`，默认 `GPU_MEMORY_UTILIZATION=${GPU_MEMORY_UTILIZATION:-0.55}`；后台启动入口为 `scripts/start_llm_qwen3_nohup.sh`。八个结构基线的原生算法适配、成本计量和预检门槛见 [统一运行说明](../../baseline/scripts/STRUCTURE_RETRIEVAL.md)。

## 7. 结果与结论的边界

- CPU 测试、tiny smoke 与冻结响应回放验证流程和重构一致性，不能替代正式效果实验，也不能保证切换 embedding 后分数不变。
- 主表只使用实际完成且逐题对齐的结果；失败/缺标注与不可评指标明确报告，不按结果删题或填零。
- 配对 Pack 局部重排分析可控制同一候选和 Plan state；Route/Plan 消融会改变下游候选，必须真实运行，不能由已有 Full 排名伪造。
- 主表跨数据集效果、MuSiQue 上的机制解释及成本结论分别限定证据范围；预算、Backbone、无 oracle-hop 和置信区间在完成前均标为计划，不写预期提升数字。
